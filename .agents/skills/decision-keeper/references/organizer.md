# Decision Keeper organizer

Work from the opted-in project root. Keep decision files inside `docs/decision/`, with `docs/decision/decision-keeper.md` as the index. For an organization request, work from the saved rules even when the input batch is empty. Keep one writer for the decision tree.

1. Read the index and follow relevant topic links to the most specific file. Reuse an existing branch when it fits. Keep a new standalone decision in the index. When a second distinct decision shares a useful topic, group them in a topic file linked from the index. A correction that supersedes the first decision counts for grouping even if only one rule survives. A restatement does not count. During maintenance, also group clear clusters already in the index.
2. Save only active policy. Keep one self-contained `- ` bullet on one physical line per decision. Replace superseded rules, retain conditions and exceptions that still apply, and preserve unrelated content. If new policy is ambiguous, report the conflict and leave the affected policy intact.
3. After routing the batch, visit every linked file, including the index. When a file exceeds 10 active decision bullets, move related rules to focused child topics and link them from the parent. Count only decisions, excluding topic links. Keep broadly applicable rules in the parent when they fit; if they alone exceed 10, group them by subject or use case so each split reduces the parent count. Check every child the same way, including children created in this pass. Finish when every file has at most 10 active decisions.
4. Put top-level topics beside the index. For any other parent named `decision-<topic>.md`, put its child files in a sibling folder named `<topic>/`. Repeat that layout at every depth. For example, `decision-delivery.md` links to `delivery/decision-fees.md`, which can link to `fees/decision-weekend.md` inside `delivery/`. Use lowercase, hyphenated `decision-*.md` filenames and links in the format `- [Topic](relative-path.md) — Description of the decisions there.` Resolve links relative to the file containing them. Put child files in place before updating parent links. Before editing existing files, check for concurrent changes and merge them if needed.
5. From the project root, run `python3` with the installed skill's `scripts/check_tree.py`. Resolve broken links, duplicate placements, unlinked decision files, and files over the limit. Compare the rules before and after: moved decisions must still be reachable, new or corrected rules must appear once, and unrelated rules must be preserved. Report changed files and any unresolved issue.

Manual entries are also eligible for recording. Preserve the supplied wording on one line. Prefix text that does not establish a lasting rule with `Note: ` so it can be read as a record. Escape an initial `[` in a rule so the tree checker reads the bullet as an entry.
